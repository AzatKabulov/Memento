# Phase 4 — accounts and offline storage

Phase 4 is underway. The app now has a native Supabase client with secure session storage, email sign-up/sign-in, confirmation callback, password reset, and sign-out. These flows activate only when a Supabase project URL and publishable key are configured. The unconfigured web build remains a clearly labelled sample diary. The [account screen preview](design/prototype-account.png) was checked at phone size; it is not proof of a live sign-in.

Native diary records are scoped to the authenticated Supabase user ID. SQLite holds versioned entry, media, preference, and pending-operation tables, with a unique active entry per owner and date. Imported or captured files are copied into app documents before a transaction commits. A failed replacement keeps the previous moment; failed copies are removed. Startup cleanup removes unreferenced files created by interrupted saves. Media paths are relative to the app documents directory so app-container path changes do not break references. Deletions leave a tombstone for later cloud sync. The app loads only the current owner's records and waits for that load before showing the diary.

Still required before Phase 4 can pass its completion gate: verify the owner-created Supabase project and email delivery, verify confirmation/reset redirects, test session restoration and offline use on iPhone and Android, and run interrupted-save/migration/account-isolation tests on devices. Google and Apple sign-in are deferred from Volume 1. Cloud backup remains Phase 7. The native store has passed TypeScript and bundle checks but has not yet been exercised on physical devices.
