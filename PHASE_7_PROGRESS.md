# Phase 7 — private backup and recovery

Phase 7 is underway. The native app now has an account-scoped, persistent sync queue. It reads remote changes before uploading local ones, uses revision checks and operation IDs to avoid silent overwrites, keeps deletion markers, resumes large media uploads in 6 MB chunks, verifies the uploaded object before saving cloud metadata, and downloads a complete media file before replacing a local entry. Sync runs while the app is foregrounded and connectivity permits. Settings shows local/waiting/backed-up/attention states, transfer progress, a Wi-Fi-only preference, manual retry, and a comparison flow for conflicting dates. The web build remains a sample preview with no cloud claim.

The server migration is [supabase/migrations/202609270001_private_diary.sql](supabase/migrations/202609270001_private_diary.sql). It creates a private media bucket, owner-only read/upload policies, a row-level protected diary table, and a compare-and-swap write function. The client never holds a service-role key. Run the migration in a Memento Supabase project before connecting the app. Then configure `mobile/.env` from `mobile/.env.example` with the project URL and **publishable** key. The project's global Storage limit must allow the selected 250 MB per-file limit. [Supabase's Free project limit is 50 MB per file](https://supabase.com/docs/guides/storage/uploads/file-limits), so the project's plan or the app's video-size target must change before full video backup works. The app can sign in only after Phase 4 authentication settings and email delivery are configured.

This is sync, not a historical backup. Supabase database backups do not include Storage media. Before promising disaster recovery, configure separate database and media-object backups, choose a retention period, rehearse restoring both into a test project, and document the operator procedure. Do not treat the cloud copy as end-to-end encrypted; it is private by server authorization.

Still required for the Phase 7 completion gate: a real Supabase project and migration; iPhone/Android uploads and fresh-device restores; two-account RLS, direct-object, expired-session, interrupted-upload, and conflict tests; a measured storage/cost allowance; a verified operator recovery drill covering media; and server-side account deletion, including Sign in with Apple token revocation once Apple sign-in is implemented. The app does not offer account deletion yet. Neither the web preview nor a JavaScript export verifies these native and server behaviors.
